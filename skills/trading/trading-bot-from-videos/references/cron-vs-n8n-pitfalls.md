# الاختيار بين Hermes Cron و n8n — الدروس المستفادة

## المشكلة

n8n استُخدم في البداية لإدارة تدفقات التداول (تقرير الصباح، إشارات) — **فشل كاملاً**.

## ماذا حدث

1. تدفقات n8n اشتغلت أول مرة فقط (22 مايو) وانتهت بخطأ في < 1 ثانية
2. لم تشتغل مرة أخرى بعدها — لا في الأحد 24 مايو ولا غيره
3. الـ REST API يتطلب مصادقة — لا يمكن فحص التدفقات برمجياً
4. قاعدة بيانات n8n تحتاج `sqlite3` مثبت — قد لا يكون موجوداً
5. لا توجد طريقة سهلة لمراقبة أو إصلاح التدفقات عن بعد بدون واجهة المستخدم

## الحل: Hermes Cron

| | n8n | Hermes Cron |
|---|-----|-------------|
| الموثوقية | ❌ فشل في أقل من 24 ساعة | ✅ النشرات والنسخ الاحتياطي تشتغل يومياً بلا مشاكل |
| المراقبة | ❌ يحتاج واجهة ويب | ✅ `cronjob list` + `last_status` |
| الإصلاح | ❌ يدوي بالكامل | ✅ `cronjob update` + `cronjob run` |
| التكلفة | ♻️ عملية node.js دائمة (200MB+ RAM) | ♻️ يشغّل عند الحاجة فقط |
| التنسيق | — | ✅ تنسيق تلغرام تلقائي |

## قواعد

1. **استخدم Hermes Cron لكل شيء** — لا n8n إلا لو فيه سبب قوي جداً
2. **اختبر يدوياً أولاً** — `cronjob run` قبل الاعتماد على الجدول
3. **إذا فشل cron run** — شغّل التحليل يدوياً بـ `terminal` مباشرة، لا تنتظر التفعيل التلقائي
4. **جدول التداول**: `30 13 * * 0-4` = أحد-خميس 4:30 مساءً مكة

## yfinance في Hermes

- `yfinance` **غير مثبت** في venv هرمس (`/usr/local/lib/hermes-agent/venv/`)
- `pip` غير موجود داخل venv هرمس
- استخدم `/usr/bin/python3` لتشغيل تحليلات yfinance
- أو ثبت يدوياً: `apt install python3-pip && pip install yfinance --break-system-packages`
- الحزمة موجودة على system Python (`pip list | grep yfinance` = 1.4.0)
