# إدارة ذاكرة النظام — بروتوكول الإشعار

## القاعدة الأساسية

المستخدم (**أبو جهاد**) هو المسؤول الوحيد عن قرار حذف أو دمج الذاكرة. دوري فقط: **الإبلاغ والاقتراح**.

## متى أبلغ؟ (🚨 إلزامي — لا تتجاهل)

- **عند 75%+** — أذكر في نهاية الرد: "🧠 الذاكرة: XX%" + عدد المدخلات. **لا أنتظر 85%.**
- **عند 85%+** — إشرار عاجل: أعرض اختصارات محددة بمقترحاتي
- **كلما زادت 5%** بعد 75% — إشعار جديد
- **🚫 لا تتجاوز 90%** بينك وبين نفسك — أبلغه أولًا قبل أن يصل 90%
- **إذا قال المستخدم كلمة "ذاكرة"** (حتى لو ما سأل عن النسبة) — أعطيه تقرير فوري
- **بعد أي تعديل كبير** (دمج، حذف، نقل للـ skills) — أبلغه بالنتيجة: كم صار الاستخدام

## سبب التغيير (من تاريخ الجلسات)

في جلسة سابقة (مايو 2026)، وصلت الذاكرة 96% وما أبلغته إلا لما سأل هو. قال:
"ايش فيها الذاكره مو قلت لك اعطيني تقرير إذا قربت تمتلئ"
**الخلاصة: أوقظه عند 75% ولا أنتظر. هو يفضل إنذار مبكر على استئذان متأخر.**

## كيف أبلغ؟

```
🧠 الذاكرة: XX% ممتلئة (X,XXX/2,200 حرف) — X مدخلات

مقترحاتي للاختصار:
- #N (...): → نقدر نختصر لـ "..."
- #N (...): → ممكن نحذف لأنه موجود في مهارة كذا
- ...

أنت القرار يا أبو جهاد 🫡
```

## ممنوع ⛔

- **لا أحذف ولا أختصر أي شي بدون إذنه** — مهما كان صغيرًا أو بديهيًا
- **لا أستبدل entry بآخر** بدون موافقته (حتى لو لتوفير مساحة)
- **لا أنقل معلومات للـ skills** بدون ما أعرض عليه الخطة أولًا

## بعد الموافقة

بعد ما يوافق المستخدم على المقترح:
1. أنفذ بالضبط اللي وافق عليه
2. أبلغه بالمقدار اللي وفرته (مثلاً: "99% → 65% — وفرنا 34%")
3. أعرض عليه نسخ احتياطي GitHub

## متى تنطبق

عندما يكون هدف التفاعل هو تقييم/تعديل حالة الذاكرة أو أي حالة نظامية أخرى تمس بيانات المستخدم (skills, config, env...).
